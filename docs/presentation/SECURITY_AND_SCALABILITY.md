## 8.1. Security — безопасность

| Тема | Статус | Что есть в коде | Риск / что улучшить |
|---|---|---|---|
| **Authentication** (кто ты?) | ✅ | Supabase Auth; бэкенд проверяет каждый JWT через `GET /auth/v1/user` (`SupabaseTokenVerifier`, таймаут 5 с, кэш 60 с) | Выход из аккаунта начинает действовать на бэкенде с задержкой до 60 с из-за кэша |
| **Authorization** (что тебе можно?) | 🟡 | Все данные фильтруются по `user_id` из токена, а не из запроса; админ — по `ADMIN_EMAILS` (`AdminUser`, иначе 403) | Нет ролей в БД; список админов — в `.env`, после изменения нужен перезапуск (ADR 0001) |
| **Input validation** | ✅ | Pydantic: длина строк, количество элементов, шаблон кода языка; бизнес-проверки в сервисах (`same_words`, длина мнемоники 3–200) | Аудио проверяется только по размеру (1 КБ–2 МБ) |
| **SQL injection** | ✅ | SQLAlchemy ORM / параметризованные запросы, нет склейки SQL из строк **[INFERRED по просмотру репозиториев]** | — |
| **Secrets** | ✅ / 🟡 | Ключи в `.env`, `.env` в `.gitignore`; ключи OpenRouter/Azure/Supabase service — только на бэкенде | Нет менеджера секретов; при деплое нужны переменные окружения платформы |
| **Изоляция файлов** | ✅ | Картинки в приватном Storage, браузер получает подписанную ссылку на 1 час | — |
| **Rate limiting** | 🟡 | AI: 30 вызовов/день на пользователя; картинки: 5 за 24 ч; одновременно максимум 4 вызова агентов | Нет общего лимита запросов на IP или эндпоинт (например, на `/sentences`) |
| **Prompt injection** | 🟡 | Ответы модели — строгий JSON, поля обрезаются, рендерятся как текст (React экранирует HTML) | Текст мнемоники ученика вставляется в system prompt Carla; модель может «послушаться» его. Риск ограничен: агент не имеет инструментов и видит только данные этого же ученика |
| **CORS** | ❌ (не нужен сейчас) | `CORSMiddleware` нет; в разработке фронтенд и API на одном origin через Vite proxy | При деплое на разные домены нужно настроить CORS с явным списком доменов |
| **HTTPS / deploy** | ❌ | Деплоя нет | Нужен хостинг с HTTPS |
| **Приватность в журналах** | ✅ | `ai_usage` хранит только счётчики и модели; сводка для админа без `user_id` и текстов (ADR 0001) | `learning_outcomes.detail` содержит тексты ученика — их нужно учитывать при удалении аккаунта |
| **Удаление данных пользователя** | ❌ | Нет DELETE-эндпоинтов и FK на пользователей | Добавить «удалить мой аккаунт» (GDPR) |
| **MCP-сервер** | ✅ | Только чтение, 5 инструментов, для разработчика | Не открывать наружу; он видит данные всех учеников |

## 8.2. Reliability — надёжность

| Механизм | Статус | Где |
|---|---|---|
| Транзакция на запрос (всё или ничего) | ✅ | `deps.get_session` → `session.begin()` |
| Единый формат ошибок | 🟡 | `AppError` → `{"detail": "..."}`; ошибки валидации FastAPI имеют другую форму (ADR 0001 признаёт это) |
| Таймауты внешних вызовов | ✅ | Supabase 5 с, Azure 15 с, Tatoeba 10 с, OpenRouter — `httpx` с таймаутом из настроек |
| Повторы (retry) | ✅ | OpenRouter: 1 HTTP-повтор на 500/502/503/524/529 + `ask_with_retry` (2 попытки); Tatoeba: 4 повтора с exponential backoff и `Retry-After` |
| Fallback | ✅ | Список запасных моделей; эмодзи вместо картинки; вежливое `message` вместо 500 |
| Graceful degradation | ✅ | Без ключей AI приложение работает: агенты показывают «not set up», карточки сохраняются без картинок |
| Идемпотентный импорт | ✅ | Tatoeba upsert по внешнему id; повторный запуск не создаёт дубликатов |
| Миграции с откатом | ✅ | 6 миграций Alembic, у всех есть `downgrade` |
| Тесты | 🟡 | pytest — 237 passed, 1 skipped (тест MCP без пакета `mcp`), включая архитектурные и контрактные тесты; Vitest — 36 тестов; CI на каждый push. **[VERIFIED]** — запущено 27.11.2026 на Python 3.12 + PostgreSQL |
| Мониторинг | 🟡 | Логи с временем ответа агента; таблица `ai_usage`; Staff room и Control Room. Нет Grafana/OpenTelemetry (план 4-й недели) |
| Расхождение окружений | ⚠️ | Локально Postgres 17, в CI — Postgres 16 |

## 8.3. Scalability — масштабирование

**Что произойдёт при росте нагрузки?** **[INFERRED]**

| Узкое место | Почему | Решение |
|---|---|---|
| Синхронные вызовы LLM | HTTP-запрос держит рабочий поток, пока модель отвечает (секунды) | Очередь задач (Arq/Celery/RQ) + polling или streaming (SSE) |
| Семафор на 4 вызова — **на процесс** | При 2 серверах лимит станет 8, а не 4 | Распределённый лимит (Redis) |
| Кэш ответов, живые статусы, кэш токенов — **в памяти процесса** | Не делятся между серверами, теряются при перезапуске | Redis |
| Бесплатные модели OpenRouter | Частые 429, нестабильное качество | Платная модель или несколько провайдеров |
| Проверка токена — сетевой запрос к Supabase | Добавляет задержку (смягчено кэшем 60 с) | Локальная проверка подписи JWT (JWKS) |
| База данных | Индексы на основных запросах есть; одна БД | Пока достаточно; позже — пул соединений и реплики для чтения |

**Что уже масштабируется хорошо:** бэкенд почти stateless (состояние в БД), слои разделены, внешние сервисы за интерфейсами — их легко заменить. **[VERIFIED по структуре]**

## 8.4. Architectural decisions — архитектурные решения

### Задокументированные (`docs/decisions/`) **[VERIFIED]**
| ADR | Решение | Почему |
|---|---|---|
| 0001 | `GET /agents/usage/summary` для админов, сначала в `openapi.yaml`, потом код (contract-first) | Видеть стоимость и сбои агентов, без личных данных |
| 0002 | Поле `is_admin` в `/agents/usage` | Показать ссылку на Staff room без нового эндпоинта; безопасность всё равно на бэкенде (403) |
| 0003 | Живые состояния агентов в памяти (`/agents/live`) | Для Control Room; простота важнее долговечности |
| 0004 | Список предложений, одно предложение и карточки — в контракт; `POST /mnemonics` отвечает `200` (создать или заменить) | Контракт по заданию курса: список с фильтром и пагинацией, get-one, запись с валидацией |

### Решения, видимые в коде (интерпретация) **[INFERRED]**
| Решение | Вероятная причина | Цена |
|---|---|---|
| Layered architecture + тест архитектуры | Порядок, тестируемость, ports & adapters (2-я неделя курса) | Больше файлов |
| Нет таблицы users, есть Supabase | Не писать свою авторизацию | Нет FK, сложнее удаление данных |
| Rule-based оркестратор вместо фреймворка агентов | Предсказуемость, тесты, бесплатные модели плохо делают tool calling | Нет автономности |
| Строгий JSON-ответ от каждого агента | Надёжный парсинг, UI знает форму данных | Модель иногда ломает формат → нужны повторы |
| История разговора в браузере | Нет таблицы и нет хранения переписки | Клиенту приходится доверять |
| Tatoeba только через CLI | Импорт данных — разовая операция, не на каждый запрос | Данные не обновляются автоматически |

## 8.5. Limitations — честный список ограничений

1. Нет деплоя — приложение работает только локально.
2. `openapi.yaml` описывает 7 операций из 33 (обязательные по заданию + админские); остальные — только в `/docs` FastAPI.
3. Агенты без памяти, без инструментов, без общения между собой.
4. Все AI-вызовы синхронные.
5. Состояние в памяти процесса (кэш, живые статусы, семафор).
6. Нет удаления данных и аккаунта.
7. Нет мониторинга уровня продакшена.
8. Качество зависит от бесплатных моделей.
9. Postgres 16 в CI против 17 локально.

## 8.6. Roadmap — план развития

| Срок | Что | Зачем |
|---|---|---|
| **Short-term** (1–2 недели) | Дописать в `openapi.yaml` оставшиеся эндпоинты; `Idempotency-Key` для `POST /mnemonics`; выровнять Postgres в CI; один формат ошибок (Problem Details); удалить данные пользователя | Контракт, честность, GDPR |
| **Short-term** | Деплой (Docker-образ + CI/CD через GitHub Actions); CORS для реального домена | Показывать продукт вживую |
| **Medium-term** (1–2 месяца) | OpenTelemetry → Grafana (логи, метрики, трейсы); Redis для кэша, лимитов и статусов | Наблюдаемость и несколько серверов |
| **Medium-term** | Персонализация: агенты получают короткую сводку из `learning_outcomes` | Агенты «помнят» слабые места |
| **Long-term** | Очередь задач и streaming; tool calling (например, поиск примеров в базе); evals — набор тестовых вопросов для сравнения моделей | Скорость, автономность, контроль качества |
